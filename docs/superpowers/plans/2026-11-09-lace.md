# Lace Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Join the document's own letters with connecting strokes drawn under the text, as an opt-in Visuals layer.

**Architecture:** A window-independent `lace` module ports the prototype: bitmap glyph → strokes (lines, arcs, dots) → connectors → ligature candidates per grid relation, cached as table entries with pre-rasterised sprites. A worker builds faces and tables off the UI thread. Each frame, a stable local selection picks entries for the visible cells, and `editor_view` draws their sprites as glyph quads between the selection highlight and the text.

**Tech Stack:** Rust 1.88.0 workspace, `texted-app` crate, std only. Existing `DrawList`/`CachedGlyph` drawing, serde settings.

**Spec:** `docs/superpowers/specs/2026-11-09-lace-design.md`. Reference prototype with expected answers: `docs/superpowers/specs/2026-11-09-lace-prototype/` (`core.js`, `font.js`, `lig.js`, `grid.js`, `vectorize.js`; run `node gridtest.js` there).

## Global Constraints

- Off by default. Settings live in `Visuals` (`#[serde(default, deny_unknown_fields)]`); files without the new field load unchanged.
- The document's glyphs render exactly as today. The lace draws only connecting strokes, below `paint_text`.
- No new dependencies. No work on the UI thread that grows with the document. Face vectorising and table building happen on a worker that notifies through the wake closure (the `DocumentStats::new(move || w())` pattern) and never captures a native window.
- Geometry is in model units: x-height = 8, measured from the glyph's own baseline; `k = 8 / (baseline − x_top − 0.5)` per face.
- Determinism: iterate pixel sets in `(y, x)` order (`BTreeSet`/`BTreeMap`, never `HashMap` iteration) so the port matches the prototype. Randomness comes from splitmix64 of `(document line, char column, relation, entry, seed)`.
- Rules from the owner: at most one ligature per pair; per letter at most one per side (forward, back, up, down; diagonals count as up/down); removal never deeper than the attachment point and never more than a quarter of the letter's ink (only an absorbed dot may exceed it, and the document glyph is drawn whole anyway); between two rows at most one connection per column pair `(0–1, 2–3, …)`; serifs ignored by default.
- Faces: available when the cell is 6–32 px wide and 8–64 px high and the face has `x` or `х` (to measure baseline and x-height); otherwise the Visuals page shows why.
- Commit messages are one plain sentence, like `Port the lace connector model`, ending with the session's attribution lines. Work on branch `feat/lace` from `main`.
- Verification before every commit: `cargo fmt --all -- --check`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, and the task's `cargo test --locked -p texted-app --lib lace::…`.

## Review Focus

1. **Characters outside the face** (emoji, CJK, tab, control characters, `U+FFFD` fallback): treated as empty cells, with no connections and no panic. Test in Task 5: `unknown_characters_are_empty_cells`.
2. **Huge documents and long lines:** work grows only with visible cells. Test in Task 5: `work_is_bounded_by_visible_cells` (a 200 000-character line in no-wrap mode builds candidates for at most the visible columns plus the margin).
3. **Fractional zoom (10 % steps):** sprites must sit on the same rounded x as `draw_string` places glyphs. Test in Task 7: `sprites_align_with_text_at_fractional_zoom`.
4. **Font or serif setting changed while the worker is busy:** stale results must be ignored, never drawn on the new face. Test in Task 7: `stale_tables_are_ignored_after_a_face_change`.
5. **Wide Verba faces** (multi-byte rows, for example 13×5): rows must be read with stride `width.div_ceil(8)`. Test in Task 2: `wide_faces_read_multi_byte_rows`.

**Files:**
- Create: `crates/texted-app/src/lace/layer.rs`

**Interfaces:**
- Consumes: `Tables::get`, `Tables::fill` (tests only), `Relation`, `Entry` (Task 4).
- Produces:
  - `pub struct Row<'a> { pub line: usize, pub start_col: usize, pub text: &'a str }`, one per visible row, top to bottom; matches `VisibleLine`.
  - `pub struct Settings { pub density: f32, pub spacing: u8, pub seed: u32 }`.
  - `pub struct Placed { pub row: usize, pub col: usize, pub entry: Arc<Entry> }`. `row` is an index into `rows`; `col` is the left/upper cell's column on screen.
  - `pub struct Selection { pub placed: Vec<Placed>, pub missing: Vec<(Relation, char, char)> }`.
  - `pub fn select(rows: &[Row], tables: &Tables, s: &Settings) -> Selection`: uses only entries `get` returns; pairs not yet filled are skipped and listed in `missing` (deduplicated) for the worker. Tests fill every missing pair and select again.

Selection order:
1. Each row on its own, in priority order (mechanism, then cost, then splitmix hash): in-word (`H`) always; across-space (`S(n)`, n ≤ `spacing`, only when all n cells between are spaces), accepted when `hash < density`.
2. Then each band (r, r+1) on its own: `V`, `Dr`, `Dl`, accepted when `hash < density`.

A candidate is accepted when none of its keys are taken. Keys are its connector keys plus `pair(a,b)`, the side slots `F`/`B`/`U`/`D`, and `band(r, col/2)`. Connectors used in step 1 stay used in step 2. Cells whose character the face lacks, or that is not alphabetic, are empty.
